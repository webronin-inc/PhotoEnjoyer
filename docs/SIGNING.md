# Подпись программы и предупреждения Windows

## Коротко и честно

Самоподписанный сертификат **не убирает** предупреждение Windows у посторонних
людей. Он нужен, чтобы:

* подтвердить, что файл собран вами и не изменён после сборки;
* доверять своим сборкам на своих/знакомых компьютерах (импорт сертификата);
* в будущем заменить файл `.pfx` на купленный сертификат — без переделки сборки.

Что происходит у обычного пользователя с самоподписанной программой:

| Ситуация | Что видит пользователь |
|---|---|
| Скачал установщик из интернета | SmartScreen: «Windows защитила ваш компьютер» → «Подробнее → Выполнить в любом случае» |
| Windows 11 с включённым «Smart App Control» | Запуск может быть **заблокирован** без возможности обойти кнопкой |
| Антивирус | Самоподписанная подпись на оценку не влияет; ложные срабатывания возможны у любых программ на PyInstaller |
| Компьютер, где установлен ваш `.cer` | Издатель показывается как «PhotoEnjoyer», предупреждений нет |

Репутацию в SmartScreen нельзя «получить» самоподписанным сертификатом — она
накапливается у файлов/издателей, которым Microsoft доверяет, и со временем растёт
скачиваниями. Это одинаково для всех сертификатов, поэтому и платный сертификат
не даёт мгновенного результата.

## Как подписывать сборки

1. Создайте сертификат (один раз):
   ```bash
   python tools/make_codesign_cert.py --out secrets --name "PhotoEnjoyer" --years 5
   ```
   Папка `secrets/` в `.gitignore`. `.pfx` и пароль — **секрет**: кто их получит,
   сможет подписывать программы от вашего имени.
2. Локальная сборка с подписью (нужны Windows SDK и Inno Setup):
   ```bat
   set PE_SIGN_PFX=secrets\photoenjoyer-codesign.pfx
   set PE_SIGN_PASSWORD=ваш_пароль
   python build.py
   ```
   Подписываются сам exe и установщик, с меткой времени (бесплатный сервер DigiCert).
3. Автоподпись на GitHub: добавьте секреты репозитория `CODESIGN_PFX_BASE64`
   (содержимое `secrets/pfx_base64.txt`) и `CODESIGN_PASSWORD`, а в шаге
   «Build EXE and Installer» файла `.github/workflows/release.yml` — переменные:
   ```yaml
      - name: Build EXE and Installer
        env:
          PE_SIGN_PFX_BASE64: ${{ secrets.CODESIGN_PFX_BASE64 }}
          PE_SIGN_PASSWORD: ${{ secrets.CODESIGN_PASSWORD }}
        run: python build.py
   ```
   Без этих секретов сборка идёт как раньше, без подписи.

## Как раздать доверие своим пользователям

Тому, кому вы доверяете и кто хочет видеть вас «известным издателем», передайте
файл `photoenjoyer-codesign.cer` **лично** и сообщите отпечаток SHA-256
(скрипт печатает его при создании сертификата). Затем на его компьютере, от
имени администратора:

```powershell
.\tools\trust_certificate.ps1 -Cer .\photoenjoyer-codesign.cer
```

Скрипт добавляет сертификат в «Доверенные корневые» и «Доверенные издатели» этого
компьютера (отменить: добавить `-Remove`). Просите ставить только сертификат,
полученный от вас лично: любой «доверенный корневой» сертификат позволяет его
владельцу подписывать программы, которым Windows этого компьютера будет верить.

## Что реально снижает тревожность у новых пользователей

1. Раздавайте установщик **со своей страницы** и покажите картинкой, где нажать
   «Подробнее → Выполнить в любом случае».
2. Не используйте UPX; по возможности собирайте в режиме «папка» (onedir), а не
   «один файл» — антивирусов он тревожит меньше.
3. Если антивирус или Defender блокирует файл ложно — отправьте его на анализ
   в Microsoft Security Intelligence («Submit a file»); это бесплатно.
4. Когда появится бюджет — купите сертификат подписи кода (OV/EV) или облачную
   подпись и положите `.pfx`/настройки в те же секреты. Код сборки менять не нужно.

## Что защищает лицензию на самом деле

Подпись кода не защищает от копирования. Исходники открыты, значит проверку входа
в клиенте можно убрать в своей сборке. Усилить защиту можно так: приватный
репозиторий и раздача установщика только вошедшим; всё ценное (библиотека
шаблонов, обновления) держать на сервере; считать вход «замком на дверь», а не
сейфом.
